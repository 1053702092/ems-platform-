# EMS 面试项目简历描述与话术

## 简历项目名称

燃料电池混合动力系统 EMS 能量管理策略对比与优化平台

## 简历 Bullet 版本

- 搭建燃料电池-电池混合动力系统 EMS 仿真平台，基于 WLTC/NEDC 工况完成车辆功率需求计算、燃料电池效率建模、电池 SOC 状态转移和能量分配策略仿真。
- 实现并对比规则控制、动态规划 DP、ECMS、MPC 等能量管理策略，统一评估原始氢耗、终端 SOC、SOC 修正氢耗、燃料电池平均效率和功率峰值。
- 发现旧版 MPC 原始氢耗低于 DP 的异常现象，分析其原因是终端 SOC 透支导致评价口径不公平，进一步提出 `H2_eq` 指标进行 charge-sustaining 修正。
- 新建优化版 MPC，加入 SOC 软下限、真实终点 SOC 欠差惩罚和燃料电池功率变化惩罚；WLTC 工况下优化版 MPC 原始氢耗 0.2432 kg，SOC_end 0.576，接近 DP 基准。
- 输出完整可视化图表和结果数据，形成可复现的 EMS 算法对比项目，为后续 PPO-RL EMS 控制器扩展打下基础。

## 30 秒面试介绍

我做了一个燃料电池混合动力系统 EMS 能量管理项目，搭建了规则控制、DP、ECMS、MPC 的统一仿真平台。项目不只比较原始氢耗，还同时看终端 SOC 和 SOC 修正氢耗。我发现旧版 MPC 看起来比 DP 省氢，其实是因为透支了电池能量，所以我又新建了优化版 MPC，加入 SOC 软约束和燃料电池功率变化惩罚，让评价更接近工程真实口径。

## 2 分钟技术介绍

这个项目面向燃料电池-电池混合动力系统的能量管理。输入是 WLTC/NEDC 工况，我先根据车辆动力学计算整车功率需求，再根据燃料电池效率曲线和电池 SOC 状态转移模型，决定每一时刻燃料电池和电池的功率分配。

算法上我实现了四类策略：规则控制作为 baseline，DP 作为离线最优基准，ECMS 作为实时等效消耗策略，MPC 作为滚动优化策略。项目里最重要的收获不是某个数值更低，而是发现了旧版 MPC 的评价问题：它的原始氢耗低于 DP，但终端 SOC 更低，说明它多用了电池能量，所以不能直接说 MPC 优于 DP。

为了解决这个问题，我增加了 `H2_eq` 作为 SOC 修正氢耗指标，并新建优化版 MPC，加入 SOC 软下限、终点 SOC 欠差惩罚和燃料电池功率变化惩罚。最终形成了从建模、算法实现、异常分析、工程修正到结果可视化的完整闭环。

## 5 分钟深挖结构

1. 项目背景：燃料电池混动系统需要在氢耗、SOC 稳定、燃料电池效率和寿命之间做多目标权衡。
2. 建模方法：车辆动力学计算功率需求，燃料电池效率曲线计算氢耗，电池模型更新 SOC。
3. 算法路线：Rule 简单可靠，DP 离线全局基准，ECMS 适合实时，MPC 可利用预测窗口。
4. 关键问题：旧版 MPC 原始氢耗低但 SOC_end 偏低，说明存在电池透支。
5. 工程修正：加入 `H2_eq`、SOC 软下限、终点 SOC 欠差惩罚、FC 功率变化惩罚。
6. 结果解读：优化版 MPC 不追求虚低原始氢耗，而是让 SOC 更接近公平比较口径。
7. 后续扩展：CLTC、多参数扫描、预测误差鲁棒性、C++/Simulink、PPO-RL 控制。

## 面试追问准备

### 为什么 DP 是基准？

DP 在已知完整工况和统一目标函数时，可以通过后向递推获得全局最优策略，因此适合作为离线理论基准。但 DP 依赖完整未来工况，计算量大，不适合直接在线部署。

### 为什么旧版 MPC 不能直接说优于 DP？

因为旧版 MPC 的原始氢耗低于 DP，同时终端 SOC 更低。这意味着它把一部分能量需求转移到了电池，相当于“少烧氢、多用电”。如果不修正终端 SOC，比较口径是不公平的。

### 为什么要用 H2_eq？

`H2_eq` 把终端 SOC 偏差折算为等效氢耗，用来避免“透支电池导致原始氢耗虚低”的误判。它不是实测氢耗，而是一个用于 charge-sustaining 公平比较的评价指标。

### ECMS 和 MPC 的区别？

ECMS 是瞬时优化，依赖等效因子把电池功率折算为氢耗；MPC 是有限时域滚动优化，可以利用未来功率需求预测，但更依赖预测精度，也有更高计算负担。

### 为什么要加燃料电池功率变化惩罚？

燃料电池频繁大幅变功率会影响系统寿命和动态响应。加入 `W_PFC_SLEW` 可以抑制功率跳变，让控制策略更接近工程部署需求。

## 面试中要避免的说法

- 不说“MPC 超过 DP，所以 MPC 更强”。
- 不说“DP 可以在线实时用”。
- 不只报原始氢耗，不提 SOC_end。
- 不把 `H2_eq` 说成真实氢耗。

## 推荐说法

- “旧版 MPC 的低氢耗暴露了评价口径问题。”
- “我用终端 SOC 和 SOC 修正氢耗做公平比较。”
- “优化版 MPC 的目标不是把原始氢耗压到最低，而是避免电池透支并兼顾燃料电池功率平滑。”
- “这个项目体现的是建模、算法对比、问题诊断和工程修正能力。”
